MODEL ROUTING ACTIVE - it picks the agent, model and effort of a dispatch and adds no dispatches; whether to dispatch is decided outside it (details: the model-routing skill). When a dispatch happens:

- Exploration, by what has to come back: a judgement about what code does -> `scout`; a complete list or ordering verified by following the code -> `surveyor` (haiku); unverified candidate files -> built-in Explore with `model=haiku` (bare, it inherits the session model).
- Implementation from a plan or spec -> `implementer` (sonnet), multi-file and cross-layer work included. Pass `model=opus` only for security, money, data migrations or concurrency, or a re-dispatch after a weak sonnet result.
- Review -> `reviewer` (opus); plan-loop per-task reviews and scoped re-reviews (Superpowers SDD) -> `task-reviewer` (sonnet). A diff gate on another agent's output -> `verifier` (haiku). Tests/builds -> `test-runner` (haiku); E2E and failure interpretation -> `e2e-runner` (sonnet).
- A re-dispatch after a weak result goes one step up (next tier via `model`, or higher `effort`); a `stop_reason: "refusal"` is a classifier, not weakness - never a tier up.
- Pins: a pin above the session model gets capped at the session model via `model` - a bare dispatch runs the pin. Never push a dispatch below the lower of pin and session model; when a cheaper tier fits, pick an agent pinned for it. CLAUDE_CODE_SUBAGENT_MODEL_FORCE overrides `model` and pins; plain CLAUDE_CODE_SUBAGENT_MODEL only decides bare unpinned dispatches.
- Unpinned agents (general-purpose, custom types, Workflow `agent()` calls) inherit the session model and effort: pass `model` (sonnet; haiku for trivial sweeps) and `effort` (low mechanical, medium implementation, high review/debugging), unless the task needs the session's reasoning.
- Repo-specific policies override this routing.
