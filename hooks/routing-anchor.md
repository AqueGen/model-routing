MODEL ROUTING ACTIVE - expensive model thinks, cheap models grind. You cannot switch the main-session model; route through the model-routing agents (rationale: the model-routing skill):

- Main session: planning, specs, docs, architecture, small interactive edits. Trivial questions answerable from context or general knowledge: answer inline - a dispatch costs more than the answer.
- Exploration, by what has to come back: a judgement about what code does -> `scout`; a complete list or ordering verified by following the code -> `surveyor` (haiku); unverified candidate files -> built-in Explore with `model=haiku` (bare, it inherits the session model). With a code-graph MCP connected, query the graph first; scout verifies file:line.
- Approved plan/spec -> `implementer` (sonnet). Pass `model=opus` (Fable sessions too) for multi-file/cross-layer work, security/money/migrations/concurrency/public contracts, or a retry after a weak sonnet result; when in doubt, opus. Ambiguous task or unclear root cause: clarify first - implementer stops on ambiguity. No approved plan: have it return its PLAN and check it here before it writes code. Batch related tasks per agent.
- Review -> `reviewer`; high-risk or large diffs get final review in the main session. Batched implementer output you will not read in full -> `verifier`, never on the main session's own work. Tests/builds -> `test-runner`; E2E and failure interpretation -> `e2e-runner`.
- Effort (low/medium/high/xhigh/max; Claude Code default medium on Opus 5.5 and Sonnet 5.5, high on most others): low mechanical, medium implementation, high architecture/debugging/review, xhigh/max only long-horizon or frontier work. On xhigh/max review only what the plan, the user or these rules ask - no self-started second round, no extra reviewer subagents. A dispatch carries no effort param: bundled agents pin theirs, Workflow `agent()` takes an `effort` opt.
- Stuck on the approach: the agent hands back; decide, then continue the same agent (SendMessage, else re-dispatch with its packaged state). Unfinished return with no blocker named: continue at the same tier. Failed or weak RESULT: fresh dispatch one tier up; a second failure comes to the main session. `stop_reason: "refusal"` is a classifier, not weakness: rephrase or drop, never re-dispatch a tier up.
- Pins: a pin above the session model gets capped via `model` - a bare dispatch runs the pin. Never push a dispatch below the lower of pin and session model; pick a cheaper-pinned agent instead. CLAUDE_CODE_SUBAGENT_MODEL_FORCE overrides `model` and pins; plain CLAUDE_CODE_SUBAGENT_MODEL only decides bare unpinned dispatches.
- Unpinned agents (general-purpose, custom types, Workflow `agent()` calls) inherit the session model and effort: set `model` (sonnet; haiku for trivial sweeps) and Workflow `effort` unless the task needs the session's reasoning.
- Repo-specific policies override this routing. A session that is one phase: suggest /model instead.
