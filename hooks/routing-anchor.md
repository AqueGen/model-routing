MODEL ROUTING ACTIVE - it decides the agent, model and effort of a dispatch and adds no dispatches; whether to dispatch is decided outside it (rationale: the model-routing skill). When you do dispatch:

- Exploration, by what has to come back: a judgement about what code does -> `scout`; a complete list or ordering verified by following the code -> `surveyor` (haiku); unverified candidate files -> built-in Explore with `model=haiku` (bare, it inherits the session model).
- Implementation from an approved plan/spec -> `implementer` (sonnet). Pass `model=opus` (Fable sessions too; the pinned medium effort stays) for multi-file/cross-layer work, security/money/migrations/concurrency/public contracts, or a retry after a weak sonnet result. Ambiguous task: clarify first - implementer stops on ambiguity. No approved plan: have it return its PLAN and check it here before it writes code. One plan task with its own verification step per implementer, one at a time; batch only small edits to the same files under one check. Review-fix lists: one agent per root cause.
- Review -> `reviewer` (opus), which also gives a verdict per external finding; only confirmed ones go to `implementer`. Plan-loop per-task reviews and scoped re-reviews (Superpowers SDD) -> `task-reviewer` (sonnet). High-risk or large diffs: final review stays in the main session. Gating another agent's batched diff you will not read in full -> `verifier`, never on the main session's own work. Tests/builds -> `test-runner`; E2E and failure interpretation -> `e2e-runner`.
- Effort (low/medium/high/xhigh/max; Claude Code default medium on Fable 5.2, Opus 5.5, Sonnet 5.5 and Haiku 5.5, xhigh on Opus 4.7, high elsewhere): low mechanical, medium implementation, high architecture/debugging/review, xhigh/max only long-horizon or frontier work. On xhigh/max review only what the plan or the user asks - no self-started second round, no extra reviewer subagents. A dispatch carries no effort param: bundled agents pin theirs, Workflow `agent()` takes an `effort` opt.
- Stuck on the approach: the agent hands back; decide, then continue the same agent (SendMessage, else re-dispatch with its packaged state). Unfinished return with no blocker named: continue it the same way at the same tier. A finished agent never takes the next task. Failed or weak RESULT: fresh dispatch one step up (next tier via `model`, or higher Workflow `effort` when the miss is shallow thinking); a second failure comes to the main session. `stop_reason: "refusal"` is a classifier, not weakness: rephrase or drop, never re-dispatch a tier up.
- Pins: a pin above the session model gets capped at the session model via `model` - a bare dispatch runs the pin. Never push a dispatch below the lower of pin and session model; when a cheaper tier fits, pick an agent pinned for it. CLAUDE_CODE_SUBAGENT_MODEL_FORCE overrides `model` and pins; plain CLAUDE_CODE_SUBAGENT_MODEL only decides bare unpinned dispatches.
- Unpinned agents (general-purpose, custom types, Workflow `agent()` calls) inherit the session model and effort: set `model` (sonnet; haiku for trivial sweeps), and on Workflow stages `effort` (cheap stages low), unless the task needs the session's reasoning.
- Repo-specific policies override this routing. A session that is one phase: suggest /model instead of delegating it.
